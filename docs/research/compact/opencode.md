# OpenCode /compact feature

updated: 20260821

---

I inspected commit [`2859603c…`](https://github.com/anomalyco/opencode/commit/2859603cbb5e346d1c32519cb3f5ee58b0d78455) of `anomalyco/opencode`.

OpenCode’s `/compact`:

1. Stores a special compaction message.
2. Sends part of the old history to another LLM for summarization.
3. Stores the summary as an assistant message.
4. Uses the summary plus recent messages when constructing future model requests.

## Call flow

`/compact` is handled as a dedicated TUI command, not as a normal user prompt.

[`packages/tui/src/routes/session/index.tsx`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/tui/src/routes/session/index.tsx#L562-L580)

```ts
sdk.client.session.summarize({
  sessionID,
  modelID,
  providerID,
})
```

The server then does this:

[`handlers/session.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/opencode/src/server/routes/instance/httpapi/handlers/session.ts#L273-L295)

```ts
compactSvc.create({
  sessionID,
  agent: currentAgent,
  model: {
    providerID,
    modelID,
  },
  auto: false,
})

promptSvc.loop({ sessionID })
```

`create()` adds an empty user message containing a special part:

```ts
{
  type: "compaction",
  auto: false
}
```

[`session.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/schema/src/v1/session.ts#L195-L202)

The session loop then detects this compaction task and calls `compaction.process()`.

## Prompt sent to the LLM

There are two prompt layers: a system prompt and a dynamic user prompt.

### System prompt

OpenCode uses a hidden agent called `compaction`.

[`agent.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/opencode/src/agent/agent.ts#L218-L234)

Its system prompt is [`compaction.txt`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/opencode/src/agent/prompt/compaction.txt).

In summary, it instructs the model to:

* Act as a context-summarization agent.
* Produce a format that another coding agent can use to continue the work.
* Follow the requested Markdown structure exactly.
* Preserve file paths, identifiers, errors, URLs, and other precise details.
* Output only the summary, not a conversational response.
* Respond in the same language as the conversation.

This agent prompt is inserted into the system message during LLM request preparation.

[`llm/request.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/opencode/src/session/llm/request.ts#L56-L112)

### User prompt

The dynamic user prompt is approximately structured like this:

```text
Here is the conversation so far:

<conversation>
[User]: ...
[Assistant]: ...
[Assistant reasoning]: ...
[Assistant tool call]: read({"filePath":"..."})
[Tool result]: ...
</conversation>

Create a new anchored summary from the conversation history
so another coding agent can continue the work.

<template>
## Objective
## Important Details
## Work State
### Completed
### Active
### Blocked
## Next Move
## Relevant Files
</template>
```

This prompt is generated by `buildPrompt()` and the summary template in [`packages/core/src/session/compaction.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/core/src/session/compaction.ts#L12-L55).

[`buildPrompt()`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/core/src/session/compaction.ts#L160-L174)

If a previous compaction already exists, the prompt also includes:

```text
<prior-summary>
Previous summary
</prior-summary>
```

Then it instructs the model to:

* Preserve previous objectives, constraints, and decisions.
* Add new information from the latest conversation.
* Prefer newer information when facts conflict.
* Move completed work from `Active` to `Completed`.
* Update `Objective` and `Next Move`.

## How the conversation is serialized

OpenCode does not send the original message array directly. It converts the history into plain text.

[`session/compaction.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/opencode/src/session/compaction.ts#L44-L120)

Examples:

* User text → `[User]: ...`
* Assistant text → `[Assistant]: ...`
* Reasoning → `[Assistant reasoning]: ...`
* Tool call → `[Assistant tool call]: tool({...})`
* Tool result → `[Tool result]: ...`
* Tool output is truncated to 2,000 characters.
* Attachments are represented by their MIME type and filename rather than their full contents.

So the summarization LLM receives a relatively simple textual transcript rather than the original structured conversation.

## Which history is summarized?

OpenCode does not summarize the entire history every time.

It divides the history into:

* `head`: older messages to summarize.
* `tail`: recent messages to preserve verbatim.

The LLM summarizes only the `head`. The `tail` remains in its original form.

By default, the recent tail is limited to roughly 25% of the usable input-token budget, with a minimum of 2,000 tokens and a maximum of 15,000 tokens.

This can be configured with `tail_turns` and `preserve_recent_tokens`.

[`config.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/core/src/v1/config/config.ts#L149-L167)

## What happens after summarization?

The summary is stored as an assistant message:

```ts
{
  role: "assistant",
  summary: true,
  parentID: compactionMessageID
}
```

The old messages are not deleted from the database. `MessageV2.filterCompacted()` hides them only when constructing the context sent to the model.

The model effectively sees:

```text
[compaction marker]
[assistant summary]
[retained recent history]
[new conversation after compaction]
```

[`filterCompacted()`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/opencode/src/session/message-v2.ts#L521-L570)

## Manual versus automatic compaction

Manual `/compact` uses `auto: false`, so OpenCode does not automatically send a continuation prompt after the summary is generated. The user’s next prompt resumes the conversation.

Automatic compaction uses `auto: true`. After summarization, OpenCode adds a synthetic user message:

```text
Continue if you have next steps, or stop and ask for clarification if you are unsure how to proceed.
```

[`prompt.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/opencode/src/session/prompt.ts#L1149-L1168)
[`compaction.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/opencode/src/session/compaction.ts#L468-L548)

Plugins can also completely replace the compaction prompt or inject additional context.

[`plugin/index.ts`](https://github.com/anomalyco/opencode/blob/2859603cbb5e346d1c32519cb3f5ee58b0d78455/packages/plugin/src/index.ts#L298-L325)

One important detail: OpenCode does not use a cheaper model for compaction by default. Manual compaction uses the currently selected model, while automatic compaction uses the model from the previous user message.
